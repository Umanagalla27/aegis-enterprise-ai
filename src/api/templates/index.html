Why Services Fail to Open & Permanent Step-by-Step Fixes

When clicking on Prometheus, Grafana, Redis, Postgres, or Airflow, browsers may show ERR_CONNECTION_REFUSED or ERR_INVALID_HTTP_RESPONSE. Here is exactly why and how to fix each:

1. Docker Services (Prometheus, Grafana, Redis, Postgres)

Root Cause: Docker Desktop daemon is stopped on Windows (Docker Desktop is unable to start).

Permanent Fix:
1. Open PowerShell as Admin and run:
wsl --update; wsl --shutdown
2. Launch Docker Desktop from Windows Start Menu.
3. Run the compose stack:

docker compose -f docker/docker-compose.yml up -d COPY
2. MLflow Tracking Server (:5000)

Status: LIVE & VERIFIED (200 OK)
MLflow UI is currently running in the background on port 5000. Open http://localhost:5000 to view experiments and artifacts.

Manual Start Command:

.\venv\Scripts\mlflow.exe ui --port 5000 COPY
3. Redis 7 Cache (:6382)

Why Browser Fails: Redis communicates via the binary RESP socket protocol, NOT HTTP. Opening http://localhost:6382 in Chrome triggers ERR_INVALID_HTTP_RESPONSE.

Zero-Downtime Guarantee: Aegis has a built-in high-speed in-memory cache fallback. The platform runs seamlessly with or without Redis!

4. PySpark Spark UI (:4040)

Why Browser Fails: The Spark Web UI on port 4040 only exists while an active SparkSession is executing. Once batch jobs terminate, port 4040 closes.

How to Run: Click Run PySpark Aggregation in the "Airflow & PySpark" tab or execute:

python data_platform/spark/batch_aggregator.py COPY
5. Apache Airflow (:8080)

Why Browser Fails: Airflow webserver requires starting airflow standalone.

Native Execution: You can run the entire DAG with 1 click in the "Airflow & PySpark" tab or via terminal:

python data_platform/airflow/dags/daily_sre_etl.py COPY
6. Helm Chart & GitOps

Why Browser Fails: Helm is a Kubernetes CLI tool, NOT an HTTP web page. The web UI for Helm releases is ArgoCD (k8s/argocd/application.yaml).

Verify Chart Syntax:

helm template k8s/helm/aegis-platform/ COPY
